## Objective

Reduce waste from documentation-only commits repeatedly triggering the full Foundation CI while preserving an always-present trustworthy status for production and integration checkpoints.

## Manager-reviewed discovery result

Manager accepts the FFH-018 discovery/design recommendation.

Accepted architecture:
- preserve one always-running workflow/job identity: workflow `Foundation CI`, job `verify`, displayed check `Foundation CI / verify`;
- do not use workflow-level `paths-ignore` or a job-level condition that can make the verify job disappear;
- classify the pull-request diff inside the always-running verify job;
- use a narrow fail-closed documentation allowlist:
  - `.ai/**/*.md`;
  - `docs/**/*.md`;
  - root-level `/*.md`;
- any path outside that allowlist forces FULL validation;
- mixed documentation + any non-documentation change forces FULL validation;
- deletion/rename semantics must be fail-closed so moving or deleting a non-doc file cannot masquerade as docs-only;
- unknown event, missing/invalid base/head, empty/unparseable diff, classifier error, or any ambiguity forces FULL validation;
- `workflow_dispatch` always forces FULL validation;
- documentation-only mode may skip only expensive dependency/application validation after the classifier and cheap AI-state checks have run;
- non-doc mode retains the existing full validation stages and order;
- workflow files, package/lock files, source, tests, migrations, scripts, configuration, and all other non-allowlisted paths are always FULL;
- emit durable evidence for mode/reason, changed paths, PR base/head, actual tested SHA, run/job identity, and executed validation;
- add durable test-output evidence without weakening command exit status or the job's failure semantics.
