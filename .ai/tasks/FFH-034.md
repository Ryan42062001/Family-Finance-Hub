## Public-runner safety amendment — 2026-09-18

After the repository became public, Manager re-evaluated the previously preserved self-hosted-runner invariant.

GitHub's current security guidance recommends against self-hosted runners for public repositories because fork pull requests can execute untrusted code on persistent runner machines. Standard GitHub-hosted runners are free and unlimited for public repositories and each normal Windows job receives a fresh GitHub-hosted VM.

Manager therefore amends FFH-034:
- replace `runs-on: [self-hosted, Windows, X64, ffh-local]` with `runs-on: windows-latest`;
- keep Windows as the operating-system class;
- keep Node 22;
- keep the same `Foundation CI` workflow name and `verify` job id;
- add least-privilege workflow permissions (`contents: read`);
- do not execute Foundation CI on the user's persistent self-hosted machine while the repository is public.

This is a CI-security hardening within FFH-034, not a product/financial/Supabase behavior change.

## Fail-closed change classification

For pull requests, classify from the PR base/head diff using rename-safe/deletion-safe evidence. Prefer a no-renames, status-aware diff so a source-file rename into an allowed docs path cannot hide the original non-doc path.

The only DOCS_ONLY paths are:
- any Markdown file under `.ai/`;
- any Markdown file under `docs/`;
- any root-level Markdown file.

Anything else => FULL.

FULL is mandatory for:
- workflow files;
- package/lock files;
- scripts;
- source/application files;
- calculation/security tests;
- migrations/Supabase;
- configuration;
- mixed docs + any non-doc path;
- deletion or rename involving any non-doc path;
- empty, missing, malformed, ambiguous, or unparseable change evidence;
- classifier failure;
- unsupported event;
- `workflow_dispatch` unconditionally.

## Cheap path

Every run still performs:
- checkout;
- Node setup;
- classifier execution;
- classifier unit tests;
- AI-state validation;
- evidence/summary generation;
- evidence artifact upload.

DOCS_ONLY may skip only:
- `npm ci`;
- production dependency audit;
- calculation tests;
- security tests;
- typecheck;
- lint;
- build.

AI-state validation must continue to run on documentation-only changes so `.ai/**/*.md` state errors cannot bypass machine validation.

## Full path

For FULL mode, run every existing Foundation CI stage with the same failure semantics and stage ordering. The implementation PR itself contains non-doc workflow/script changes and therefore MUST exercise FULL mode.

No classifier outcome may convert a non-doc or ambiguous run into DOCS_ONLY.

## Durable observability

Every verify run must expose in `GITHUB_STEP_SUMMARY` and a small durable evidence artifact:
- classification: FULL or DOCS_ONLY;
- classification reason;
- event name;
- PR number when present;
- PR base SHA and head SHA when present;
- actual workflow-tested SHA (`github.sha`, including the PR merge SHA when applicable);
- changed path/status evidence;
- workflow run id/number and verify job identity;
- which validation stages executed versus were intentionally skipped.

For FULL runs, capture executed test/validation output into the evidence artifact while preserving console visibility and exact command exit/failure semantics.

Use `actions/upload-artifact@v4` with `if: always()` so evidence survives failures. Keep retention bounded (target 14 days unless live repository policy requires a smaller supported value). Do not upload secrets, environment values, Supabase credentials, user financial data, node_modules, build output, or repository contents unrelated to CI evidence.
