### FFH-013-R03 / P03 — MEDIUM — strict calendar-date validation for invalid ISO-looking dates

Accepted helper contract:
- absent date => 12;
- invalid date => 12;
- tax-year mismatch => 12;
- January current tax year => 12;
- September => 4 including September;
- December => 1.

Current defect: JavaScript Date normalization can turn impossible dates such as `2026-09-31` into a valid later date and return an incorrect shorter horizon.

Required behavior:
- syntactically ISO-looking but calendar-invalid dates are rejected as invalid and use the 12-month fallback;
- do not rely only on `Number.isNaN(new Date(...).getTime())`;
- preserve valid leap-year/calendar semantics correctly.

Required direct tests at minimum:
- `2026-09-31` => 12;
- `2026-02-30` => 12;
- `2026-02-29` => 12 because 2026 is not a leap year;
- valid `2024-02-29` for tax year 2024 behaves as a valid date;
- clearly unparsable => 12;
- wrong tax year => 12;
- `2026-09-01` => 4;
- `2026-12-01` => 1.
