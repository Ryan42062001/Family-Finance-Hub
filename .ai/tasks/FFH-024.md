### Verified findings

- Current official Supabase documentation still supports `migration list`, `migration repair`, linked `db push`, `db push --dry-run`, and `--include-all`.
- `migration list` compares local/remote migration versions only; identical SQL under different versions remains divergent.
- `migration repair` changes migration tracking only and does not apply/revert migration SQL.
- Read-only remote-history inspection proves `20260829180242 household_foundation` stores the executable SQL corresponding to repository `0001_household_foundation.sql`.
- Read-only remote-history plus live-catalog inspection proves `20260903135253 phase_5b_goal_intelligence` corresponds to repository `20260903134156_phase_5b_goal_intelligence.sql`; all 8 added columns, all 11 named constraints, and both repository comments were verified live.
- Phase 5A is genuinely unapplied: both its history row and expected schema column are absent.
- FFH-010 and FFH-011 remain genuinely unapplied.

### Recommended supported sequence

1. Manager authorizes one App/Data executor and freezes concurrent migration deployment.
2. Executor verifies current CLI/version/help, authenticates/links securely, confirms target, and takes a protected pre-change backup including migration-history evidence.
3. History-only canonicalization, one command/evidence step at a time:
   - mark repository `0001` applied;
   - verify;
   - mark remote-only `20260829180242` reverted;
   - verify;
   - mark repository `20260903134156` applied;
   - verify;
   - mark remote-only `20260903135253` reverted;
   - verify.
4. Run `supabase migration list --linked`; all historical rows must align except the three genuinely pending migrations.
5. Run `supabase db push --linked --include-all --dry-run`; it must show **exactly**, in order:
   - `20260902190000_phase_5a_hybrid_retirement_floor.sql`
   - `20260909005000_ffh_010_hsa_input_contract.sql`
   - `20260909033000_ffh_011_simple_plan_limit_contract.sql`
6. Stop for Manager authorization of the live DDL step.
7. If authorized, App/Data executes canonical repository `supabase db push --linked --include-all` and performs FFH-020 post-deployment verification.
