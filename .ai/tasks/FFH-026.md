# FFH-026 — Production Deployment & Release Readiness

Owner: Application, Data & Integration Engineer
State: QUEUED
Execution mode: STANDARD_CHAT / Work-mode optional when live deployment complexity warrants it
Roadmap phase: Phase 7 — Deployment & Release Readiness
Approved target: stable `main` release candidate after Phase 5 and Phase 6 acceptance

## Objective
Establish a verified production deployment of Family Finance Hub before Private Beta, including a stable application URL, production environment configuration, production Supabase readiness, security-critical smoke validation, and release/rollback evidence.

This task is intentionally queued. Do not activate it while Phase 5 or Phase 6 correctness/integration work remains open.

## Dependencies
FFH-026 may activate only after Manager verifies all of the following:
- Phase 5 — Money Priority Engine is accepted and integrated into the intended stable release baseline;
- Phase 6 — Scenario Lab is accepted and integrated;
- required Supabase migration/history recovery and production verification tasks, including FFH-020 / FFH-016 or their successors, are closed or explicitly superseded;
- no release-blocking security regression remains open;
- the intended production release SHA is identified.

## Scope
When activated, the owner must:
1. Create or verify the Vercel production project for Family Finance Hub.
2. Configure production environment variables and secrets through supported secure mechanisms; never commit secret values.
3. Verify the intended production Supabase project, authentication configuration, callback URLs, and required migrations against the exact release candidate.
4. Deploy the exact Manager-approved release candidate to production.
5. Capture the stable production URL and deployment identity.
6. Run production smoke tests covering at minimum:
   - sign-up / sign-in / sign-out and confirmation callback;
   - protected-route enforcement;
   - household onboarding;
   - dashboard reads;
   - planning tools;
   - Money Priority Engine critical flows;
   - Scenario Lab critical flows;
   - safe incomplete/unknown-data behavior.
7. Re-verify database-layer privacy and cross-household isolation in the deployed environment using privacy-safe test households/evidence.
8. Verify no production secret or sensitive user data appears in repository, logs, screenshots, or handoff artifacts.
9. Establish and document a rollback path for application deployment and any release-associated migration failure.
10. Decide whether the default stable Vercel production URL is sufficient for Private Beta or whether a custom domain is required; do not purchase/configure a paid domain without explicit user authorization.
11. After the production URL is verified stable:
    - add it to the GitHub repository About → Website field;
    - update the README with the production URL and deployment status.
12. Return exact deployment, validation, and rollback evidence to Manager before Private Beta activation.

## Non-goals
- Do not use this task to redesign product features.
- Do not weaken security/RLS/auth requirements to achieve a deployment.
- Do not deploy an unaccepted Phase 5 or Phase 6 branch.
- Do not run unapproved migration-history repair or database DDL outside the accepted migration plan.
- Do not expose credentials, service-role keys, account data, SSNs, or real household financial records in evidence.

## Acceptance criteria
- Exact production release SHA is recorded.
- Vercel production deployment succeeds and maps to that release SHA.
- Production URL is stable and reachable.
- Production environment variables/secrets are configured securely.
- Production Supabase linkage/auth callbacks/migrations are verified.
- Required smoke tests pass with exact evidence.
- Cross-household security isolation is independently re-verified in production-safe testing.
- Rollback instructions are documented and feasible.
- GitHub About → Website contains the stable production URL.
- README reflects the production URL/status.
- Manager independently verifies the evidence and explicitly authorizes progression to Private Beta.

## Next gate
Remain `QUEUED` until Phase 5 and Phase 6 are accepted and the production release candidate is identified. Manager owns activation and final acceptance.
